# 项目文档

这里统一存放产品、设计和开发文档。分类从项目早期就固定下来，后续新增文档时放入对应类别，避免所有文件重新堆在同一级。

## 产品文档 `product/`

- [愿景与定位](./product/vision.md)：解释网站是谁的、服务什么目标，以及“数字基地”和“数字花园”的关系。
- [功能需求](./product/requirements.md)：记录页面职责、内容原则和功能边界。

## 设计文档 `design/`

- [视觉系统](./design/visual-system.md)：记录设计令牌、四套皮肤、布局、响应式和多语言设计。
- [可访问性](./design/accessibility.md)：记录键盘、语义、对比度、动效和触控目标要求。

## 开发文档 `development/`

- [架构与目录](./development/architecture.md)：说明完整目录树、文件职责、路由与数据流，开始改代码前优先阅读。
- [代码注释规范](./development/code-commenting.md)：说明教材级注释应解释什么、如何组织折叠区段。
- [前端学习地图](./development/learning-map.md)：把知识点对应到仓库中的真实代码。

## 维护规则

- 文档只保留在 `docs/`，不再同时维护 `doc/`。
- 路径、文件职责或构建产物发生变化时，同步更新架构文档。
- 新文档先判断属于产品、设计还是开发，再放入对应子目录。
