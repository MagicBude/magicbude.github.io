# 教材级注释规范

源码既是产品实现，也是学习材料。注释质量通过“是否帮助理解决策”衡量，而不是数量衡量。

## 文件头必须回答

1. 文件负责什么？
2. 输入来自哪里，输出到哪里？
3. 与哪些 HTML、CSS 或 JavaScript 文件协作？
4. 加载顺序为什么不能改变？
5. 修改它最容易破坏什么？

## 注释应该解释

- 为什么选择 Flex、Grid、某个断点或某个浏览器 API。
- 为什么某段脚本必须在 CSS 之前或 DOM 之后运行。
- 无障碍、兼容性、安全和无脚本降级边界。
- 改变常量、选择器或数据结构会影响哪些页面。

不要写“给变量赋值”“循环数组”这类代码本身已经表达的信息。

## 分区规范

- HTML：`<!-- #region 页面头部 -->`
- CSS：`/* #region 语义颜色令牌 */`
- JavaScript：`// #region DOM 渲染`

分区按职责划分，标题使用可定位的中文短语。修改逻辑时必须同步检查相邻注释；失效注释属于缺陷。

涉及 `data-*`、ARIA、存储键和脚本加载顺序时，注释还要写清它与哪个文件共享约定，
避免只改一端后出现视觉正常、语义或状态已经失效的问题。
